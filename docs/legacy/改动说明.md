### 一次我造成的故障（已记录）

3:25 做「安装 → 失败 → 自动回滚」演练时，脚本用 `Stop-Process -Force` 强杀了正在运行的实例。
当时 `Local Storage\\leveldb` 正在写入，被强杀后数据库损坏，**之后每次启动都在 Chromium 初始化阶段 CHECK 失败秒退**
（表现：进程不存在、无 stderr、无崩溃报告、无事件日志）。

定位过程：真实 `app.asar` 哈希未变 → Defender 关闭且无拦截 → 资源文件完好 → 无锁文件残留

授权数据真实位置（扫描确认）：

- 激活令牌 JWT 在 **`Network\\Cookies`**（Chromium 加密 cookie）
- `Local Storage` 里只有 `machineCode / macAddress / computerName` 这类设备指纹缓存和 UI 偏好

所以修复只挪 `Local Storage` / `Session Storage` / `IndexedDB`，**绝不动 `Network`**，修完仍是已激活。

## 一、已完成

### 痛点 1：文件夹排序 ✅

侧边栏「文件夹」标题下方多了一行控件：**排序下拉框** + 主题按钮 + 性能开关。

| 选项 | 依据 |
| --- | --- |
| 默认顺序 | 原始 `folderStore.json` 顺序 |
| 名称 A→Z / Z→A | 文件夹名（日期命名的文件夹天然按时间排） |
| 数量多→少 / 少→多 | DOM 上 `.folder_quantity[fileNum]` |
| 时间新→旧 / 旧→新 | 从 `folderStore.json` 的 `modificationTime` 读，走新增的 `whale:folderStore` IPC |

- 子文件夹（`.childFolderGroup`）同样生效。
- 选择记在 `localStorage`，重开还在。
- 用 `MutationObserver` 跟随：应用重绘列表后会自动重新排序，不会「排完又弹回去」。

### 痛点 2：节点信息里的「提示词」识别 ✅（本轮最有价值的一项）

原逻辑只认节点自己身上写死的 `text`：

```js
// 原始 Ea()（压缩后）
if (api.isPromptInput(t, r)) { ... }
if (Pa(s)) return "";          // 只要是连线就整行丢掉
```

所以当提示词来自上游（`PrimitiveStringMultiline` / `StringConcatenate`）时，CLIPTextEncode 那一行是空的。

**你的库里的实际情况（我扫了 4639 张）**：

| 提示词来源节点 | 出现次数 |
| --- | --- |
| `PrimitiveStringMultiline` | 13,846 |
| `StringConcatenate` | 1,403 |
| `PreviewAny` | 26 |
| `Switch any [Crystools]` | 2 |
| `WD14Tagger\|pysssss` | 1 |
| **提示词走连线的图片** | **3,452 张 / 74.4%** |

新实现（`mod/mod.js` 的 `resolvePrompt`）：

1. 沿连线递归上溯（最多 5 层，带环检测）；
2. `StringConcatenate` 按 `string_a`/`string_b` 逐段解析，并用节点自己的 `delimiter` 连接；
3. 只认 `value / text / string* / prompt / positive` 这类键名，**不会把 `model`、`ckpt_name` 误当提示词**；
4. 命中后整条链上的节点都打上「提示词」标签并描边高亮，提示词行左侧有蓝色竖条，标题旁标注来源（如 `来自 PrimitiveStringMultiline`）；
5. 长提示词默认折叠 6.5 行 + 遮罩，点「展开全部」展开；每行带复制按钮；
6. 非提示词的连线输入不再被丢弃，显示为 `↑ #12 UNETLoader`，方便顺着图看。

节点面板改为**整块重绘**（`tickNodePanel` 每 400ms 比对当前选中图，变了才重绘），不修改原 bundle 一个字节。

### 痛点 3：亮色主题 ✅

原主题是 `dark-rjvU-oNx.css` 里一整套 `--color-*` 设计变量。亮色版在 `mod/mod.css` 里用 `html[data-whale-theme="light"]` 覆盖同一组变量，并补了几处写死颜色的兜底（body 背景、滚动条、tooltip）。

侧边栏按钮一键切换，选择存 `localStorage`。

⚠️ 主 CSS 里仍有少量写死色值的地方，第一版可能局部不协调——截图发我，我按图修。

### 额外：性能开关（实验，默认关）

侧边栏的 ⚡ 按钮，打开后给 `.imageDisplayUnit` 加：

```css
content-visibility: auto;
contain-intrinsic-size: 240px 300px;
```

让浏览器跳过离屏卡片的渲染/绘制。**默认关闭**是因为瀑布流是 JS 绝对定位的，我没法在这里实测，不想默认改你的布局。你打开试一下，如果滚动变流畅且没有空白卡片，就说明有效。

### 上次「点开就没」的原因

你双击的是 `_work\portable\鲸鱼图库.exe` 本身，**没带 `--user-data-dir`**。主进程字节码里确实有：

```js
app.requestSingleInstanceLock()
```

它和当时仍在运行的正式版抢同一个 profile 锁，抢不到就 `app.quit()` —— 不建窗口、不弹错误、进程直接消失。

另外两点：
- 「发布者未知」是 SmartScreen 对**新路径**下未签名 exe 的正常提示，正式版同一个二进制也这样，点「仍要运行」没问题；
- 你的 `resources\app.asar` 从未被改动（12,665,745 字节，修改时间仍是 1 月 2 日），正式版本体完好。

### 如果还是起不来

先看 `_work\portable\whale-boot.log`：

| 最后一行 | 含义 |
| --- | --- |
| 只有 `boot` | 入口跑了，之后什么都没写 → 字节码加载器挂了 |
| `loader ok` 后没有 `whale-mod ok` | 数据通道模块出错（已单测通过，概率低） |
| `app code loaded` 但没有 `app ready` | 原字节码跑起来了，卡在窗口创建前 |
| `app ready` 之后进程消失 | 窗口建了又被关，或渲染进程崩了 |
| 文件根本没生成 | Electron 没进到 `out/main/index.js`（`resources/app` 没被识别） |

把那几行发我即可。

## 四、痛点 4、5（本轮没做完，说明原因）

### 4. 导入并行 / 监听文件夹

已经埋好探针：主进程默认加载了 `mods/ipc-logger.js`，会把每次 IPC 的通道、入参、耗时、返回值写进 `_work\ud-dev\ipc-calls.log`（8MB 上限）。

**需要你做一次**：在便携版里正常导入 3~5 张图，然后把 `ipc-calls.log` 发我。
拿到真实的调用形态后，我才能：
- 判断导入是「一次调用传整批」还是「每张一次」——后者才能并行；
- 用同样的参数驱动自动导入（监听你的 `D:\Recreation\ComfyUI-aki-v3\ComfyUI\output`，发现新文件就自己喂进去）。

现在硬写的话，参数猜错会把图片导入成脏数据，不划算。

### 5. 上千张卡顿

已确认瓶颈方向：`out/renderer` 里 `.imageDisplayUnit` 是**每张图一个 DOM 节点**，4510 张就是 4510 个；筛选时整块重排，所以卡 4~5 秒。

真正的解法是**虚拟滚动**（只渲染视口内的卡片），这必须接管应用的网格渲染函数，改动量大且需要反复实测。本轮的 ⚡ 开关是低风险的第一刀，先看有没有明显改善，再决定要不要做虚拟化。
