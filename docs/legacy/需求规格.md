# WhaleNext 需求规格 v0.2

> 变更：① MVP 只做外链，不做托管/多库；② 堆叠策略按实测数据重写；③ 新增「查看器 + 胶片条 + 对比」；④ 云备份改为 U 盘备份。
> 依据：对现有 4,508 张真实数据的标定（见 §3.6 表）。

---

## 0. 范围

| 项 | MVP | 后续 |
| --- | --- | --- |
| 存储模式 | **仅外链（Linked）** | 托管模式 |
| 库数量 | 单库、单根目录 | 多库 |
| 规模设计目标 | **10 万张**（20 万不崩，50 万需换方案） | — |
| 联网 | 不依赖 | — |
| 备份 | **U 盘镜像** | 云同步（另行讨论） |

**50k 与 200k 的真实差别**（不在 UI）：
- 向量索引常驻内存：10 万 × 768 维 float32 ≈ 300 MB，200 万 ×1.5 的 HNSW 结构开销
- 全量重建索引耗时线性增长
- 缩略图缓存：10 万 × ~15 KB ≈ 1.5 GB

结论：按 10 万设计，不做分库/磁盘索引那套复杂度。

## 1. 数据模型

### 1.1 实体

| 实体 | 关键字段 |
| --- | --- |
| **Asset** | id, path, size, mtime, created_at, **content_hash**, w, h, rating(0–5), note, is_deleted |
| **SourceMeta** | prompt_json, workflow_json, positive, negative, model, loras[], sampler, steps, cfg, seed, denoise |
| **Derived** | thumb_256/512, colors[], dhash, image_embedding, nsfw_score |
| **Folder** | id, name, parent_id, physical_path（外链模式下直接映射磁盘） |
| **Tag / AssetTag** | name, category, color ／ asset_id, source(manual\|auto\|prompt) |
| **PromptTerm** | asset_id, term(归一化), polarity(pos\|neg) — 供统计 |
| **Stack** | id, member_ids[], reason(time+prompt\|near-dup), created_by(auto\|manual) |
| **SavedView** | 筛选条件 JSON（智能文件夹） |

### 1.2 三条铁律

1. **原图永不改写**——只读源文件。
2. **索引可重建**——删 `.db` + 缩略图目录，全量扫描即恢复；评分/备注/标签**双写**一份旁挂 JSON（`<根>/.whale/index-overrides.json`）。
3. **操作可回滚**——删除是软删除；任何批量操作写操作日志。

### 1.3 外链模式（MVP 唯一模式）

- 记录绝对路径，零拷贝。ComfyUI `output` 原地不动。
- 启动时抽检 5% 的路径有效性；失效则按 `content_hash` 在已知根目录内重定位。
- 根目录变更时提供「重定位向导」。

## 2. 界面

### 2.1 左区 · 数据管理

- 物理目录树（直接映射磁盘），节点显示图片数
- 筛选：评分 / 标签 / 模型 / 采样器 / 分辨率 / 时间 / 有无提示词
- 文件夹排序：名称 / 数量 / 时间（旧程序缺）
- 批量：评分、打标、软删除、导出

### 2.2 中区 · 浏览

- **虚拟化网格 / 瀑布流**，只渲染视口 ±1 屏
- 缩略图三级：256 占位 → 512 → 悬停加载原图
- 排序：名称 / 创建时间 / 修改时间 / 评分 / 分辨率 / 大小 / 随机
- 多选（框选 + Ctrl/Shift）、拖拽
- **堆叠交互**：缩略图右下角显示 `2/64` 角标；**按住 Ctrl + 滚轮/↑↓** 在组内切换，画面原地更换而不跳出

### 2.3 右区 · 元数据

- 节点列表（按 workflow 顺序），显示 class_type / 输入 / 连线
- **提示词解析**：沿连线递归上溯（`PrimitiveStringMultiline`、`StringConcatenate` 等），正负分离
- 关键参数：模型、LoRA（名+权重）、采样器、Steps、CFG、Seed、尺寸
- 一键复制：正提示词 / 负提示词 / API JSON / 完整 workflow
- 原始 JSON 折叠查看

### 2.4 查看器（Viewer）— 新增为一等公民

从网格双击进入，是三块之外的第四个主要界面。

```
┌──────────────────────────────────────────┐
│  ‹   [ 图片主区：缩放/平移/适应 ]   ›    │
│                                          │
├──────────────────────────────────────────┤
│ 123/4508   ★★★☆☆   名称 大小 时间 ▾    │
│ ┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐  ← 胶片条     │
│ └──┘└──┘└──┘└──┘└──┘└──┘                │
└──────────────────────────────────────────┘
```

**胶片条**
- 显示**当前堆叠组**的成员（不是全库），横向滚动、虚拟化
- 排序切换：**名称**（按模型前缀聚合）/ **文件大小**（按分辨率与放大层级聚合）/ 时间
- 点击切换主视图，当前项高亮
- 组内位置显示 `3/64`

**对比模式**（胶片条上多选 2–4 张）
- **并排**：2/4 宫格，缩放与平移**联动**
- **叠加**：上层透明度滑杆 0–100%，用于对比原图 vs 放大/修复结果
- 差异高亮（可选，后续）：像素差阈值染色

**键盘**
- `←/→` 上一张/下一张（全库顺序）
- `Ctrl+←/→` 组内切换
- `空格` 对比模式开合
- `1–5` 打分，`0` 清除

## 3. 功能

### 3.1 总览 Dashboard

- **词频**：正/负向分开，归一化到 Danbooru tag 体系
- **表现洞察**：每个词条的样本量 N、平均评分、≥4 星占比、**lift**（含该词 vs 不含该词的评分差）
  - N < 20 标灰，不参与排行（避免"3 张 5 星"的假信号）
- 模型 / LoRA / 采样器 / Steps / CFG 分布
- 时间趋势：日出图量、评分率、均分

### 3.2 视觉相似检索

- 主：SigLIP / CLIP image embedding
- 兜底：dHash + 颜色直方图（毫秒级，用于近重复）
- 可限定在当前筛选集内搜索

### 3.3 语义搜索

- 同模型文本塔，ONNX Runtime + DirectML
- 中文查询支持（选多语言 SigLIP 或中文 CLIP）

### 3.4 Pipeline（监听收割）

- 监听目录 → 目标逻辑文件夹映射
- 防抖：文件大小稳定 2s + 可读锁检测
- 幂等：`content_hash` 去重
- 失败重试队列 + 日志

### 3.5 连拍堆叠（按实测重写）

#### 结论先行

**只用「时间 + 提示词相似度」做主分组，图片相似度只做二次合并与非门槛信号。**

依据（4,508 张实测）：

| 时间窗 | Jaccard 阈值 | 组数 | 平均组规模 | 最大组 | 单图组占比 |
| --- | --- | --- | --- | --- | --- |
| 10 min | 0.7 | 1,574 | 2.9 | 64 | 56.4% |
| **30 min** | **0.7** | **1,456** | **3.1** | **64** | **55.7%** |
| 60 min | 0.7 | 1,419 | 3.2 | 64 | 55.8% |
| 180 min | 0.5 | 1,378 | 3.3 | 64 | 55.7% |

- **Jaccard 从 0.5 调到 0.9，组数只变 4%** → 阈值不敏感，取 0.6 即可
- **组内 dHash 距离中位数 26 / 64** → 同组图片视觉差异极大，**图片相似度若当门槛会把多模型组拆散**
- 最大组 64 张 = `2026-03-01/test1` 下 8 个模型前缀 × 8 变体，正是复杂工作流场景

#### 算法

```
1) 按 created_at 升序排列资产
2) 主分组：与「前一张」比较
     Δt ≤ 30min  AND  prompt_jaccard(前, 当前) ≥ 0.6   → 同组
   否则开新组（链式传递，适应批内微调提示词）
3) 二次合并：跨组若存在 dHash ≤ 6 的配对且 Δt ≤ 24h → 合并
   （实测全库仅 86 对 / 76,294 次比较，代价可忽略；覆盖"很久以后才做放大"的情况）
4) 上限：单组 ≤ 256，超出按时间切分
5) 增量：新资产只重算前后 1 小时邻域；成员删除后重算该组
6) 手动：合并 / 拆分 / 排除，人工结果优先且不被自动覆盖
```

#### 组内排序（查看器胶片条）

| 排序 | 用途 |
| --- | --- |
| **名称** | 文件名前缀 = 模型名 → 同一模型的图聚在一起（实测 `CKNB036_`/`WAI16_`/`NoobV_` 等） |
| **文件大小** | 分辨率与放大层级（RTXVSR 输出体积显著更大） |
| 时间 | 生成先后 |
| 相似度 | 以当前图为基准由近及远（后续） |

#### 验收用例

- 用 `2026-03-01/test1` 那 64 张验证：应聚成 1 组、`名称`排序能按模型分组、`大小`排序能把放大图排到末段
- 用一天中 3 次独立生成（提示词不同）验证：应分成 3 组，不误合并

### 3.6 备份（U 盘）

- 增量镜像到 U 盘：`<USB>/.whale/` 存索引与覆盖数据，图片按原相对路径镜像
- 清单文件（manifest）记录 size + mtime + hash，仅复制变化的
- 校验模式：抽样哈希比对，报告损坏/缺失
- 断点续传、失败清单

## 6. 边界

- 不做多用户、网络共享库、模型生成
- 云同步暂缓；若要做，只做客户端加密备份，不做规避审核的混淆（见 v0.1 说明）
